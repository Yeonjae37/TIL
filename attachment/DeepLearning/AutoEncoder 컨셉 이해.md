## AutoEncoder란?
-----------
![session](autoencoder.png)

위 그림처럼 입력과 출력이 대응되는  직관적인 구조입니다. 
그림을 그대로 따라가보겠습니다. 
1) 입력 x: "A" 손글씨 이미지
2) x가 인코더를 지나며 특징(파랑색 동그라미)으로 압축.
3) 특징들이 더 압축되어 잠재 벡터 z(초록색 동그라미) 형성.
4) 디코더가 z를 다시 펼쳐 은닉표현(분홍색 동그라미)으로, 그리고 더 복원되어 출력 x' 생성.

요약하자면 아래와 같네요.
인코더: 입력 x를 z로 압축
디코더: z를 복원해 x' 출력
입력 x ----(압축)----> 저차원 벡터 z ----(복원)----> 출력 x'

여기서 핵심은 출력 x'가 입력 x와 얼마나 비슷한가(잘 복원했는가)입니다. 이 복원률에 따라 AutoEncoder의 성능이 결정됩니다. (근데 또 너무 잘 복원하면 오히려 분리력이 떨어질 수 있습니다.... 이건 차치하고 컨셉만.. )

직관적인 이해를 위해 "복원률" 이라는 단어를 썼는데요. AutoEncoder는 보통 "재구성 오차(reconstruction loss)"라는 단어를 주로 씁니다. 원본 데이터(x)와 재구성된 데이터(x') 사이의 차이인 재구성 오차를 최소화하는 것을 목표로 한다고 이해해주시면 더욱 정확합니다.

AutoEncoder는 크게 아래 3가지 구조로 이루어집니다.
- Encoder
- Latent Space
- Decoder

**Encoder**
- 입력 데이터 x를 저차원 잠재 공간(Latent Space)으로 사상.
- 입력 차원보다 낮은 차원으로 줄여나감. 
- 중요한 특징만 남기고 불필요한 정보는 버리는 역할.

**Latent Space**
- Encoder에 의해 압축된 저차원 표현인 z가 존재하는 공간. 
- 보통 입력 데이터의 차원보다 작음.
- 데이터의 핵심적인 특징들만 응축되어 담겨있음.

**Decoder**
- z를 다시 입력 차원으로 복원해 x' 생성
